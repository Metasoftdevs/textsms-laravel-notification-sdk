# T-17 - CI hardening

**Date:** 2026-11-05, Africa/Nairobi. **Status:** workflow implementation prepared and independently reviewed; full acceptance pending actual matrix/audit execution. **Owner:** Codex.

## Plan and boundary

Expand the existing Laravel 12 workflow to PHP 8.2/8.3/8.4 and both
lowest/stable dependency resolutions, with fail-fast disabled so one
failure does not hide the other results. Lowest resolution also prefers
stable releases. Validate Composer metadata strictly before resolution;
run dependency audit against the graph installed in the PHPStan job after
its update. Keep the existing analysis/style jobs and supported-major
constraints. No Laravel 13 or PHP 8.5 claim is introduced.

Installed Testbench/plugin constraints do not prove that Laravel 12.0 is
resolvable. CI must resolve each actual graph from all runtime/dev
requirements, then run the suite. The locally installed graph is only one
stable example; it is not evidence for other PHP rows or lowest support.

## Evidence limits before editing

An independent agent attempted an offline Composer lowest dry run with
`COMPOSER_DISABLE_NETWORK=1` and `--dry-run --prefer-lowest --prefer-stable
--no-scripts --no-plugins --no-interaction --no-progress`. It exited 100:
required Packagist metadata was unavailable locally. No graph was resolved,
installed or tested; no dependency/lock/vendor file was changed. No network
fetch was attempted after that failure.

Workflow changes can be prepared, YAML-parsed and independently reviewed
locally. Actual matrix and audit results require CI or another equipped
environment. Do not mark T-17 fully accepted or widen T-18 constraints from
static workflow syntax, a solver dry run or the current PHP 8.2 suite.
Commit/push/remote workflow triggering still requires owner authorization.

## Implemented workflow and verification

The Pest workflow now defines six Laravel 12 rows: PHP 8.2/8.3/8.4 crossed
with prefer-lowest/prefer-stable. It validates root Composer metadata,
resolves the full graph for each row with stable-release preference and
runs Pest against that installed graph. Fail-fast is false. The PHPStan
workflow validates metadata and audits the lock generated by its own
dependency update. Existing PHPStan/Pint jobs and declared Composer
constraints remain in place.

Both workflow files parsed successfully using PyYAML 6.0.3's BaseLoader;
the derived matrix contains the intended six rows. Local Composer 2.7.6
help confirms `audit --locked --no-interaction` options. Independent source
review found no implementation blocker in graph selection, validation/audit
ordering or failure visibility. This is static/source evidence, not GitHub
Actions execution. The existing cache path remains unchanged; its runner
effectiveness is not a correctness guarantee.

The final local SDK gate passed **229 tests, 1245 assertions**, seed
1793871865, with PHPStan, Pint, strict Composer validation and whitespace
checks clean. That PHP 8.2 installed graph does not validate the other rows.
No lowest graph, remote audit, PHP 8.3/8.4 run or CI success is claimed.

**Intent/invariant and recovery:** CI must expose dependency-floor and PHP
differences rather than assuming them from constraints. A failed solver,
audit or test row is a real readiness failure; do not suppress it or widen
support to bypass it. Inspect the resolved graph and fix at its owning
boundary.
